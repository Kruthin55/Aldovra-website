# Aldovra — project notes for Claude

Aldovra (aldovra.com) is a career platform for Indian students and freshers: fresher jobs, assessments, resume analysis, a career agent, a student leaderboard, and an HR side for recruiters. The founder talks in Telugu written in English letters; reply the same way, short and friendly.

## Stack
- Static HTML pages at the repo root, hosted on GitHub Pages (`CNAME` = aldovra.com). A push to `main` deploys the site.
- Supabase project `lgefwfrjzweayfxahogs`: Postgres with RLS, edge functions in Deno (`supabase/functions/`), pg_cron, pg_net, and the vault secret `aldovra_cron_secret` for cron auth.
- Every database change goes in `supabase/migrations/` (timestamped .sql) and is also applied to the live project.
- Payments go through PayU edge functions (Razorpay is retired).

## Job pipeline (the most important part)
Goal: show students only live fresher or entry-level jobs in India, with new jobs arriving daily and closed ones disappearing automatically, at no cost.

| Piece | What it does | Schedule |
|---|---|---|
| `sync-job-sources` | About 200 company boards (Greenhouse, Lever, SmartRecruiters, Ashby, Workday CXS), 5 sources per call | every 3 min |
| `sync-amazon-jobs` | amazon.jobs India public JSON; cursor kept in the job_sources row (provider amazon, enabled=false on purpose) | :07 and :37 |
| `check-job-links` | Asks the employer's own API whether a posting is still live; a 404 means closed right away. Circuit breaker: if more than 60% of one provider looks closed, nothing is closed that run | every 20 min |
| `refresh_job_freshness()` | Retires stale or expired jobs, archives safely (never touches jobs that students saved or applied to), writes daily stats | 03:05 IST |
| `job-pipeline-health` + `.github/workflows/job-pipeline-health.yml` | Public health JSON; the hourly GitHub Action fails (and emails the owner) when `ok` is false | hourly |
| Daily Claude check (scheduled task "Aldovra daily job pipeline check", `trig_01TZ63k7u3ws8PL1eYV1bKnd`) | Runs `job_pipeline_health()`, cron runs, source errors, feed quality (company share, heading-like titles, >30-day rows, duplicates) and edge logs; may disable up to 5 sources that errored for 24 h+ or fix a small isolated pipeline bug; pushes a Telugu-English summary to the founder | 09:13 IST daily |

- Experience classifier: keeps "fresher" and "Entry level" (0–1 and 0–2 year ranges are fine). It rejects roles that need years of experience and senior ("Sr") titles. Titles are read with `_ | /` turned into spaces (Workday titles like "IN_RBAI_Senior …" hid "Senior" from `\b`), and the dashboard also rejects titles starting with "Mgr" and titles naming years ("6 - 10 yrs", "2+ yrs"; "0-1 yrs" stays) (6 Nov 2026; the backend `sync-job-sources` classifier was not changed, so a few such rows still carry "Entry level" in the DB but the dashboard and public pages hide them). The same logic lives in the backend and in the dashboard function `noExperienceEligible` (`assets/dashboard/dash-jobs.js`).
- Workday board token format is `tenant__wdN__site`.
- Students see only jobs posted in the last 30 days (`student_active_opportunities`: `coalesce(posting_date, created_at::date) >= today-29`; the old 90-day "still seen on board" exception was removed 29 Oct 2026). The view must keep `security_invoker = true`; `create or replace view` drops it, so re-set it after any change.
- Adding sources (29 Oct 2026): the edge function's `validate_source`/`save_source` need a signed-in admin, so new boards were probed straight from Postgres with `net.http_get` / `net.http_post` (Workday: POST `https://{tenant}.{wdN}.myworkdayjobs.com/wday/cxs/{tenant}/{site}/jobs` with `{"searchText":"India","limit":1}`; read `net._http_response`), and the ones with India listings were inserted by migration `20261029173000_add_52_job_sources.sql` (Deutsche Bank, JLL, Abbott, Applied Materials, Novartis, Medtronic, Visa, PubMatic, Fivetran, Glean, Appian, …). Probed with no India jobs or no board: Pinterest, Robinhood, Brex, Ramp, Cohere, Walmart, Dell, Qualcomm, Honeywell, most Indian IT services firms on SmartRecruiters.
- Not used:
  - Adzuna costs £8/month after its trial; it is deferred, and its code is gated on keys.
  - Jooble (free) is waiting on an API key. Keys go only into Supabase Edge Function secrets (`ADZUNA_APP_ID`, `ADZUNA_APP_KEY`, `JOOBLE_API_KEY`), never into chat or the code.
- The Microsoft careers API returns 403, so it is skipped.
- Free GitHub job repos had no license and little data, so we use the public employer APIs directly instead.

## Payments (PayU)
- Pricing rules (agreed 27 Oct 2026): the first assessment is free. Every later new-skill verification costs ₹50 if the student's latest exam score is 65% or more, otherwise ₹100. Same-skill reattempts are priced from that attempt's score (below).
- New skill flow: `create-assessment-request`, when payments are live and the student already has a request, creates the request with `status='payment_pending'` plus `unlock_fee`. The dashboard shows "Pay ₹X to unlock", `create-payu-payment` handles `purpose='new_skill'`, and `payu-callback` approves the request on payment.
- `/payu-test.html?t=<token>` is a one-time test checkout (test mode only). Create the token in `platform_settings.payu_test_token` with SQL.
- Reattempt fee is decided on the server from the latest score: 65–74% → ₹50, 0–64% → ₹100, 75%+ → passed, so no reattempt. The 24-hour cooldown (changed from 1 week on 28 Oct 2026) and the cap of 4 attempts per 30 days are enforced before payment.
- `create-payu-payment` validates the request, inserts an `assessment_payments` row (`provider='payu'`, `status='created'`), and returns signed hosted-checkout fields. The browser POSTs a form to PayU.
- `payu-callback` (surl/furl, verify_jwt off) checks the reverse hash, key, amount and owner, then confirms with PayU's `verify_payment` API before setting `status='paid'`. It redirects to `dashboard.html?payment=success|pending|failed`.
- `generate-assessment` consumes the paid entitlement through `consume_assessment_reattempt`.
- Public pricing copy (29 Oct 2026): assessment-pricing.html (price table), refund.html (full refund for duplicate/failed charges or unstarted attempts within 7 days; no refund once an attempt starts; refunds in 5–7 working days), terms.html §4, get-started.html and before-you-begin.html all state the same rules as the code (₹50/₹100, 24 h cooldown, 4 attempts per 30 days).
- Go-live switch: `platform_settings.reattempt_payments_live`, read through the RPC `reattempt_payments_live()`. While it is false, reattempts stay free and the pay buttons are hidden. Flip it with SQL once live keys are tested.
- Secrets: `PAYU_MERCHANT_KEY`, `PAYU_MERCHANT_SALT`, `PAYU_MODE` (`test` | `live`). The old Razorpay functions are disabled stubs.
- Payee name (13 Nov 2026): PayU refuses to change the UPI/merchant name to ALDOVRA without a GST certificate, so UPI apps show the proprietor's KYC name.
