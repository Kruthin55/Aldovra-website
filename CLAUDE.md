# Aldovra — project notes for Claude

Aldovra (aldovra.com) is a career platform for Indian students and freshers: fresher jobs, assessments, resume analysis, a career agent, a student leaderboard, and an HR side for recruiters. The founder talks in Telugu written in English letters; reply the same way, short and friendly.

## Stack
- Static HTML pages at the repo root, hosted on GitHub Pages (`CNAME` = aldovra.com). A push to `main` deploys the site.
- Supabase project `lgefwfrjzweayfxahogs`: Postgres with RLS, edge functions in Deno (`supabase/functions/`), pg_cron, pg_net, and the vault secret `aldovra_cron_secret` for cron auth.
- Every database change goes in `supabase/migrations/` (timestamped .sql) and is also applied to the live project.
- Payments go through PayU edge functions (Razorpay is retired).

## Job pipeline (the most important part)
Goal: show students only live fresher or entry-level jobs in India, with new jobs arriving daily and closed ones disappearing automatically, at no cost.

| Piece | What it does | Schedule |
|---|---|---|
| `sync-job-sources` | About 150 company boards (Greenhouse, Lever, SmartRecruiters, Ashby, Workday CXS), 5 sources per call | every 3 min |
| `sync-amazon-jobs` | amazon.jobs India public JSON; cursor kept in the job_sources row (provider amazon, enabled=false on purpose) | :07 and :37 |
| `check-job-links` | Asks the employer's own API whether a posting is still live; a 404 means closed right away. Circuit breaker: if more than 60% of one provider looks closed, nothing is closed that run | every 20 min |
| `refresh_job_freshness()` | Retires stale or expired jobs, archives safely (never touches jobs that students saved or applied to), writes daily stats | 03:05 IST |
| `job-pipeline-health` + `.github/workflows/job-pipeline-health.yml` | Public health JSON; the hourly GitHub Action fails (and emails the owner) when `ok` is false | hourly |

- Experience classifier: keeps "fresher" and "Entry level" (0–1 and 0–2 year ranges are fine). It rejects roles that need years of experience and senior ("Sr") titles. The same logic lives in the backend and in the dashboard function `noExperienceEligible` (`assets/dashboard/dash-jobs.js`).
- Workday board token format is `tenant__wdN__site`.
- Not used:
  - Adzuna costs £8/month after its trial; it is deferred, and its code is gated on keys.
  - Jooble (free) is waiting on an API key. Keys go only into Supabase Edge Function secrets (`ADZUNA_APP_ID`, `ADZUNA_APP_KEY`, `JOOBLE_API_KEY`), never into chat or the code.
- The Microsoft careers API returns 403, so it is skipped.
- Free GitHub job repos had no license and little data, so we use the public employer APIs directly instead.

## Payments (PayU)
- Pricing rules (agreed 27 Oct 2026): the first assessment is free. Every later new-skill verification costs ₹50 if the student's latest exam score is 65% or more, otherwise ₹100. Same-skill reattempts are priced from that attempt's score (below).
- New skill flow: `create-assessment-request`, when payments are live and the student already has a request, creates the request with `status='payment_pending'` plus `unlock_fee`. The dashboard shows "Pay ₹X to unlock", `create-payu-payment` handles `purpose='new_skill'`, and `payu-callback` approves the request on payment.
- `/payu-test.html?t=<token>` is a one-time test checkout (test mode only). Create the token in `platform_settings.payu_test_token` with SQL.
- Reattempt fee is decided on the server from the latest score: 65–74% → ₹50, 0–64% → ₹100, 75%+ → passed, so no reattempt. The 24-hour cooldown (changed from 1 week on 28 Oct 2026) and the cap of 4 attempts per 30 days are enforced before payment.
- `create-payu-payment` validates the request, inserts an `assessment_payments` row (`provider='payu'`, `status='created'`), and returns signed hosted-checkout fields. The browser POSTs a form to PayU.
- `payu-callback` (surl/furl, verify_jwt off) checks the reverse hash, key, amount and owner, then confirms with PayU's `verify_payment` API before setting `status='paid'`. It redirects to `dashboard.html?payment=success|pending|failed`.
- `generate-assessment` consumes the paid entitlement through `consume_assessment_reattempt`.
- Public pricing copy (29 Oct 2026): assessment-pricing.html (price table), refund.html (full refund for duplicate/failed charges or unstarted attempts within 7 days; no refund once an attempt starts; refunds in 5–7 working days), terms.html §4, get-started.html and before-you-begin.html all state the same rules as the code (₹50/₹100, 24 h cooldown, 4 attempts per 30 days).
- Go-live switch: `platform_settings.reattempt_payments_live`, read through the RPC `reattempt_payments_live()`. While it is false, reattempts stay free and the pay buttons are hidden. Flip it with SQL once live keys are tested.
- Secrets: `PAYU_MERCHANT_KEY`, `PAYU_MERCHANT_SALT`, `PAYU_MODE` (`test` | `live`). The old Razorpay functions are disabled stubs.

## Other decisions
- Assessments come from the resume: `analyze-resume` auto-creates one request per catalog skill found in the resume (alias-aware). While payments are off they are `approved` (free); once payments are live for the student only the first is free and the rest are `payment_pending` ("Pay ₹X to unlock", or "Unlocks after your free first exam" before any attempt). The manual skills grid (`#skillsSection`) is hidden by CSS.
- Resume-gated skills (28 Oct 2026): students only see and can request skills found in their analyzed resume (`skills`, `tools`, `technologies`, `programming_languages`, `technical_areas`), matched with aliases in `assets/aldovra-resume-skills.js` and the mirror `supabase/functions/create-assessment-request/resume_skills.ts` (server returns `SKILL_NOT_IN_RESUME`). Skills already attempted stay visible. Keep the two alias lists in sync.
- Exam proctoring (28 Oct 2026): `assets/aldovra-proctor.js` stores a camera photo (320px) + screenshot (960px) at random gaps of 10–30 s (never tell students the interval) and on suspicious events (tab hidden, blur, fullscreen exit, screen share stopped, blocked shortcut), 16 kbps audio and `timeline.json` under `assessment-evidence/<user>/<session>/` (~8–9 MB per 20-min exam instead of ~80 MB of video). `submit-assessment` saves `audio_path`, `timeline_path`, `snapshot_count` (paths must be inside the student's own folder). Viewer: `assets/aldovra-evidence-viewer.js` (hr-preview, admin "View snapshots"). Students do not see their snapshots; the dashboard result shows only an integrity summary (event counts).
- Result UI: `assets/aldovra-result-review.js` renders the dashboard "View Result" (score ring, stats, verification tracker, inline YouTube-link form, topic bars, integrity summary) and exposes `AldovraVideoLink.mount()`, also used on the post-exam result screen (`assets/aldovra-result.js`).
- Question bank (28 Oct 2026): `generate-assessment` draws questions from `question_bank` via `pick_assessment_questions()` (30/50/20 easy/medium/hard, low-exposure first). `question_exposures` records every question each student has seen, so reattempts never repeat a question; questions served 400 times retire. If the bank cannot cover a student, live Gemini generation runs (told which questions to avoid) and its questions are saved into the bank. `refill-question-bank` (cron `aldovra-question-bank-refill`, every 5 min) adds ~40 Gemini questions to the neediest skill until each has 300 active; options are stored shuffled and the prompt keeps options similar in length. Stats: `question_bank_stats()`.
- AI resilience (28 Oct 2026): if Gemini fails, `analyze-resume` reads the PDF text (unpdf) and matches catalogue skills (`analysis_mode: keyword_fallback`, `needs_ai_retry: true`); cron `aldovra-resume-ai-retry` (:17/:47, `queue_resume_ai_retries()`, max 6 tries, last 7 days) re-runs full AI analysis with the cron secret (`analyze-resume` has verify_jwt off and checks users itself; cron-only `dry_run`/`force_fallback` flags exist for testing). `generate-assessment` order: unseen bank questions → live Gemini (45 s timeout) → reuse the student's oldest-seen questions (`pick_assessment_questions(..., p_allow_reuse => true)`). `refill-question-bank` pauses 1 hour on Gemini 429 (`platform_settings.question_bank_refill_pause_until`) and targets 500 questions for skills with 20+ requests in 30 days.
- AI cost guard (28 Oct 2026): AI runs only on Gemini (resume analysis, live question fallback, bank refill); everything else (jobs pipeline, career agent, matching) is rule/SQL based and free. `ai-todays-fresher-jobs` (paid OpenAI search, unused) is a retired 410 stub. Resume uploads are capped at 5 per student per 24 h by trigger `student_resumes_daily_limit`. Cron `aldovra-cron-history-cleanup` keeps 7 days of `cron.job_run_details`. `cleanup-exam-evidence` also accepts `{"purge":[{bucket_id,name}]}` (cron secret) for one-off cleanups; on 28 Oct 2026 all legacy test videos were purged (storage ~299 MB → 0.5 MB).
- Exam screen: questions are not selectable/copyable and carry a faint watermark (email · session · date) so leaked screenshots are traceable.
- Evidence retention: `cleanup-exam-evidence` runs nightly 02:41 IST (cron `aldovra-evidence-cleanup`) using `evidence_cleanup_candidates()`: below 75% → 7 days, 75%+ → 90 days, abandoned/orphan → 7 days, resumes keep newest 2. POST `{"dry_run":true}` previews. Privacy policy section 6 states these rules.
